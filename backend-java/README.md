# 巡变智判 Java 后端

Spring Boot 管理账号、批次权限、执行状态、预测结果和协同复核，Python运行已有SeCoR变化检测模型及本地Qwen问数。当前采用单个Java应用与单GPU模型服务，供小规模课题组协作。

2026-11-12：新增“单图建筑分割”任务类型，使用冻结SCFP/SAM权重，共用本后端的上传、任务调度、GPU准入、控制台、对话、精修与报告；数据字段按任务类型区分。已有100张分割结果已登记到统一批次。原8788已改为兼容跳转；参见 [分割接入说明](../segmentation/README.md)。

## 使用

在 Windows 双击项目根目录的 `start_java_backend.cmd`，打开 http://127.0.0.1:8786/ 。结束使用时运行 `stop_java_backend.cmd`，它只停止这个新后端登记的两个进程。

1. 首页是原版巡检控制台。未登录会转至`manage.html`，登录后返回原入口；“账号与批次”负责上传和成员管理。初始管理员账号为`admin`；本机管理员凭据保存在WSL用户的`~/.config/xunbian-backend/initial-admin.json`，可在Windows资源管理器打开`\\wsl.localhost\Ubuntu-22.04\home\halcyon\.config\xunbian-backend\initial-admin.json`。登录后可通过“修改密码”更新。凭据不写入源码、日志或测试报告。
2. 管理员在“成员管理”创建账号。批次默认归创建者，创建者在“管理协作者”分配只读（查看、问数、导出）或协作（另含执行、取消、重试、复核）权限；管理员可管理全部批次。
3. 填写批次名称和区域，选择登记的检测模型。
4. 分别选择前、后时相文件。对应文件的主文件名需要相同；同一时相不能出现重名。每批最多200组，单文件最多50MB，单张最多16777216像素。
5. 点击“上传并开始预测”。页面显示逐样本进度，部分失败时可只重试失败项；上传与重试共用创建者的待处理配额。
6. 批次显示“可分析”后，点击“进入巡检控制台”。在顶部选择批次，进入区域后可查看影像、智能问答、协同复核和报告；“分析任务”可生成方案、执行查询和生成带证据引用的简报。问候和普通聊天不执行SQL；问数先经过原有对话判断和口径澄清，再调用SQL模块。各人的会话分别绑定认证用户、批次与会话编号；切换批次会开始新会话。
7. 点击“查看与复核”，核对前后时相与预测掩膜，记录“确认变化／伪变化／暂不确定”。两个成员同时提交旧版本时，后提交者收到冲突提示，需载入最新记录；修改历史保留。
8. 复核更新后，控制台刷新到新版本并清空旧会话显示；可查询`reviewed`或`review_verdict`，人工结论不会改写原模型预测。报告页按当前区域和筛选范围重新请求服务端统计，保留原版Word兼容`.doc`导出（HTML格式，非DOCX）；分析任务可导出JSON证据，“账号与批次”另有结构化JSON报告。
9. 默认进入原版5,984组全量样本库，保留来源摘要。原始数据不覆盖，人工精修保存为独立版本；管理员可授权普通成员查看或协作。新批次不凭空填入事件分类、置信度或风险等级。

分析任务区分“当前对象”和“排名候选范围”。例如选择LEVIR后问“当前区域变化率比第三高区域高多少”，方案会明确提示以LEVIR为对象、在本批次全部区域中排名；确认方案后才执行，始终不能越过批次授权。普通单区域查询仍只读取该区域。当前“变化率”默认采用各样本`changed_ratio`的均值，差值可用原始比例或百分点表达；两者不能混作相对变化百分比。

区域排名查询必须返回候选区域标识，修复SQL后继续检查候选范围。用户要求差值时，缺少差值计算的方案会进行一次有界修复；仍缺失则不接受。SQL执行但没有记录、或必要统计为NULL时，显示结果不足与尚未回答的步骤，不将整项分析标为完成。简报的数值、引用和受支持表达式的单位检查是有限检查，不保证任意SQL与自然语言完全等价。旧版分析方案需重新生成，不能复用其缓存完成状态。

简报允许按已核验的SQL单位将原始比例乘100展示为百分比、将原始比例差乘100展示为百分点差，并检查四舍五入；不能靠改列名或模型提供的展示值授权换算。检查仍绑定引用行，防止引用错区域、重复乘100或混淆百分比与百分点。比较少量区域时检查双方名称及结果引用，避免六条结论上限挤掉对比对象。简报未通过时只重写简报一次，不重复执行SQL；仍失败则保留原始结果和两次诊断。

模型处理RGB双时相影像，使用发布包的methodA预处理、256像素切块及0.5阈值。大于256的影像切块推理并合并到原尺寸；没有真值标签时不计算F1/IoU。WHU和SYSU权重来自现有 `H:/SeCoR-Net-clean/inference_release/checkpoints/`，本次没有重新训练检测模型。

## 数据流

浏览器上传 → Java校验配对与影像 → MySQL保存批次/样本任务 → Python实际预测 → Java核对掩膜尺寸、变化像素与比例 → 事务保存预测记录 → 完整批次发布 → 本批数据问数。

新结果存入独立MySQL数据库 `xunbian_backend`。问数时，Java从已保存记录生成不可覆盖的批次数据集，Python复用现有ModelSQL，在隔离只读SQLite上执行大模型生成的SQL。它能查询本次新增预测结果，但不把模型生成的SQL直接发送给原MySQL业务库。

合并入口复用原控制台外观和Word导出，所有数据通过同源Java授权接口取得，不再内嵌历史全集或调用旧端口。分析任务复用原AnalysisTasks；问数使用ConversationAssistant及ModelSQL。历史原始文件未覆盖，原有预测记录保留。精修操作详见根README“人工精修与两个结果视图”。多边形精修、草稿/审批及原始/修正两种结果视图已接入同一批次服务；旧训练入口和独立视觉语义演示不属于该业务链路。

## 自然语言问数怎样工作

控制台把原问题、当前批次和正在浏览的区域分别传给服务端。可见区域不是隐藏筛选条件：只有“这个区域／当前区域／这里”等指代才绑定它；明确指定WHU或要求“各区域”时，仍按问题查询。“该区域／刚才那个区域”保留由已执行查询结果确定的指代；缺少唯一区域时显示候选选项。查询范围下拉框另用于明确限定可查询数据。

统一对话入口先区分实际查询、普通聊天与解释/写作/不执行请求。问候夹带查询时仍处理查询；“几个图片／几张影像”在问数中规范为样本组数量（一组前后时相计1），界面显示该口径。文件或资产数量不能用样本组数冒充。数量问题的模型计划若错误列出sample_id，会先反馈修复计划，再生成SQL；不会将模型自己的列名冲突当作需要用户补充的业务条件。

之后仍由本地模型生成结构化查询要求和SQL，经过已有字段、语法树、作用域和只读校验执行；SQL出错时有限修复，缺少业务选择时澄清。聊天不覆盖查询集合或待确认选项。当前QLoRA仍仅用于原排名状态更新，没有因为修复路由和页面指代而重新训练模型。

例如：在LEVIR页面问“你好吗，这个区域有几个图片”，应查询LEVIR样本组数；问“WHU这个区域有几张图片”，应查WHU；问“各区域各有几张图片”，应返回当前批次所有区域。问“请解释这句话，WHU有几张图片”或“只写SQL，不要执行”，不访问样本表。启动后用Ctrl+F5刷新旧标签页以加载最新上下文传递逻辑。

## 后端机制

- 持久化批次、逐样本任务、执行尝试及预测结果；前端关闭不影响后台任务记录。
- 数据库执行槽限制同时领取的预测任务，初始并发1；计算期间不持有数据库事务。
- 心跳续租和过期回收；每次执行带独立attemptId，迟到结果不能覆盖新执行。
- 预测记录、资产登记和成功状态在同一个短事务中提交。统计值与掩膜不一致时拒绝入库。
- 全批成功后才发布分析数据集；保留原始影像、模型标识及批次来源。
- Java/Python接口绑定本机并使用服务令牌；浏览器不能指定服务器文件路径或模型路径。
- Java运行Linux目录中的JAR副本，重新构建不会覆盖正在运行的JAR。
- Spring Security会话认证、CSRF和逐批授权覆盖影像、问数、复核、导出；禁用账号或修改密码会使旧登录失效。失败登录限流；只有管理员能创建/禁用账号或重设其他成员密码。
- 单GPU模型请求受统一准入限制，问数队列默认最多2个请求、每人1个、最多等待30秒；后台按批次轮转，不会在大批次内部耗尽全部样本后才处理下一批。正在执行的单次推理不抢占。
- 每人默认最多1000个PENDING/RUNNING样本。暂时连接故障或显式503等采用持久化退避；服务仍不可用时先探测再派发。读超时标记结果不确定，不自动立即重复推理。
- Actuator/Micrometer记录模型调用、问数等待、队列和结果状态；`/actuator/metrics`仅管理员可访问，不把用户/任务ID作为指标标签。

正常停止Java时，正在等待模型的任务保留租约，重启后在默认60秒租约到期时恢复。显式取消的任务不会自动恢复。连续3次租约过期后显示失败，等待用户检查并重试。模型计算可能重做，结果保存按任务及当前执行尝试约束。

## 给课题组部署

默认仍监听`127.0.0.1:8786`，不会自动开放Windows防火墙或公网端口。成员从各自电脑访问，需要部署机具备可达的局域网入口；WSL网络转发/防火墙按课题组实际主机配置。Python8787及MySQL保持内部访问。

- 局域网HTTP试用可显式设置`XB_BIND_ADDRESS=0.0.0.0`再重启；界面也支持普通非安全HTTP主机名，不依赖仅安全上下文提供的randomUUID。
- 正式共享建议使用HTTPS反向代理，模板见`deploy/nginx.conf.example`。同机代理部署时启用`SPRING_PROFILES_ACTIVE=proxy`和`XB_SECURE_COOKIE=true`，Java保持回环。代理必须覆盖X-Forwarded头；该profile仅信任同机回环代理，以正确校验外部HTTPS域名与端口。
- 已验证反向代理头与外部HTTPS Origin/非默认端口的实际HTTP接口兼容性；没有代替课题组部署真实域名、TLS证书或对外网络。单Java实例的会话和模型准入是当前边界，水平扩容需再设计共享协调。

如果忘记管理员密码，可由部署机所有者在本机执行`~/.venvs/trust-agent-demo/bin/python backend-java/scripts/reset_admin.py`，新随机密码写入私有`admin-recovery.json`，不会打印到终端。管理员也能在成员管理中重设其他成员密码。

## 环境

后端运行在WSL Ubuntu-22.04。JDK与Maven安装于当前WSL用户的 `~/.local/share/xunbian-tools/`；项目启动脚本显式加载环境，Windows原Java 8没有覆盖。

- Temurin JDK 21.0.13，Maven 3.10.0：官方归档校验通过，完整来源和校验值保存在上述目录的 `installation.json`。
- Spring Boot 3.5.16，MariaDB JDBC 3.5.11（连接现有MySQL 8.0 Unix socket）。固定修复版本，避免[CONJ-1372](https://jira.mariadb.org/browse/CONJ-1372)首次认证失败；没有改动原MySQL网络监听。
- Python沿用 `~/.venvs/trust-agent-demo/bin/python`，补充bitsandbytes 0.50.2用于本地7B的NF4推理。文本模型按需加载，状态适配器只在既有状态更新分支启用。
- 数据库服务账号与内部令牌保存在 `~/.config/xunbian-backend/backend.env`，权限0600；不放在项目源码或浏览器中。
- 新数据库：`xunbian_backend`；自动化测试专用数据库：`xunbian_backend_test`。

## 验证命令

在WSL执行：

```bash
bash backend-java/scripts/maven.sh test
bash backend-java/scripts/verify-real.sh
~/.venvs/trust-agent-demo/bin/python -m pytest tests -q
```

`verify-real.sh`会创建一批带明确“真实端到端验证”标签的记录，使用已有公开影像的前后时相实际运行模型，再对新批次执行计数、区域均值、前N名、集合追问和区域排名追问，与独立MySQL SQL核对。它属于功能检查，不是检测准确率、通用Text-to-SQL准确率或QLoRA提升实验。

本版验收明细见 `backend-java/DELIVERY.md`。`verify_batch_switch.py`验证跨批会话隔离；`verify_recovery.py`会暂停并重启这个新Java后端，以重复拼接影像验证实际进程恢复，最后恢复正常60秒租约。普通使用不必运行这些验证脚本。

协作版验收使用`backend-java/scripts/verify_group.py`与`tests/group_collaboration_browser.cjs`，分别验证实际图像/模型/数据库链路和两账号浏览器流程。`tests/group_ui_regression.cjs`覆盖不安全HTTP API兼容、切换样本的在途请求、退出清理和模型离线时的已有批次查看。浏览器验证前先运行verify_group生成私有QA账号文件；结果存于`evaluation/group_collaboration_20261101/`。

控制台合并版使用`backend-java/scripts/verify_console_merge.py`及`tests/console_merge_browser.cjs`。后者覆盖登录回跳、原控制台问答、协作复核、Word下载、分析任务及切换在途请求；使用前者产生的私有本机QA账号，结束验收后禁用这些临时账号。合并证据保存在`evaluation/console_merge_20261102/`。上段协作版浏览器脚本是旧界面的历史验证记录，不作为新版首页验收脚本。

验证工具默认读取私有初始管理员凭据；若管理员已修改密码，请用`XB_ADMIN_CREDENTIAL_FILE`指定另一个私有凭据文件。可通过`XB_EVAL_OUTPUT`把原有验证脚本的结果写到新目录，避免覆盖历史验收记录。

`tests/java_backend_browser_smoke.cjs`使用Playwright做真实上传、影像显示、计数问数和澄清按钮检查。测试依赖可通过 `XB_PLAYWRIGHT` 与 `XB_BROWSER` 指定本机包和Chromium浏览器路径。

完整测试与失败记录放在 `evaluation/java_backend_20261101/` 及项目 `logs/java-backend-*.log`。首轮缺少量化依赖、驱动冷认证及排序方向误判的记录保留；不把这些失败从最终过程记录中删除。

## 已有代码的最小修复

真实联调发现原排名解析器会让“并列时区域ID升序”覆盖主指标降序，已补充双向回归并按主排序方向解析。另将“查询未读取数据表”的反馈具体化，要求模型修复FROM，而不是向用户询问本已存在的样本数据。这些是查询链路修复，没有新增SQL微调或声称模型准确率提升。
