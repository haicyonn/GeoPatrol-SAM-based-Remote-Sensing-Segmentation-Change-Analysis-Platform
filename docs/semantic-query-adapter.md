# 多轮问数语义适配实验

这是独立的离线实验，生产入口仍使用现有查询流程和原排名适配器。新适配器没有替换 SQL 模型，也不直接生成答案。

## 实现范围

输入原话、页面区域、物理数据范围、上一条成功执行的任务、真实选中样本及待澄清问题，输出固定任务协议：聊天/查询/澄清、区域、指标、筛选、分组、排名、统计对象与比较基准。

实验桥接 `tools/semantic_query_session.py` 将通过验证的任务转为明确查询要求，交给原 `ModelSQL` 流程；SQL 仍由基座模型生成，沿用原有校验、只读执行和反馈修复。执行失败不提交新任务状态；聊天保留待澄清问题；对选中样本求和后保留原集合。

`query_semantic_protocol.py` 内另有任务到 SQL 的确定性编译器，仅用于检查标签和评分，不能把它当成大模型生成 SQL 的效果。

## 数据与训练

- 冻结数据：`training/query_semantic_data_v2_20261102`，768 条训练、96 条验证、192 条测试，24 类场景。监督标签由手写措辞和程序化场景构造，不是公共基准或教师模型蒸馏。
- 数据按照措辞家族与完整输入划分；目标区域在候选表中的位置随机化。测试中85条含新区域名，但新区域与任务类别存在混杂，不能据此比较新旧区域泛化率。
- 固定缓存版本 Qwen2.5-Coder-7B-Instruct，NF4、LoRA r16/alpha32、all-linear、只计算回答部分损失；完整随机遍历训练数据一次，中途与末尾检查点只由验证集选择。
- 测试在选定检查点后推理。保留原始输出、模型和数据哈希、训练覆盖及显存记录。

## 评测解释

先检查完整任务匹配，再将任务在三份对比 SQLite 数据上执行。评审发现第一版测试数据把“已复核”与“高风险”偶然关联；已将两列独立变化，并用错误 SQL 回归测试确保能辨别。原始训练运行记录保留，最终审计使用更新后的评分器重新评分，不改变检查点选择。

增加两个诊断，防止只学会 JSON 格式却被描述成业务理解改善：

1. 对两种模型的原始输出做相同的等价表示归一化，只有空筛选、空默认值与全区域列表等编码变化，不修正指标或区域判断。
2. 基座和适配模型分别使用同样五条固定训练示例，作为更强的提示对照。示例在测试推理前固定，不能从测试错误中挑选。

另有8组、24轮冻结完整对话，以每个系统自己的实际历史继续执行。对照保留完整原流程；候选使用新语义适配器和同一 SQL 流程。实际生成的 SQL 在三份数据上重放，忽略输出别名但要求结果形状和数值正确。澄清需要匹配具体原因，不能把任何追问都判对。

## 运行与查看

在项目根目录，用已有 WSL Python 环境运行。训练会占用显存，服务控制脚本只暂停已确认归属本项目的进程，并在成功或失败后分别尝试恢复，避免一个服务失败导致另一个无法恢复。

```bash
python tools/train_query_semantic_qlora.py --data training/query_semantic_data_v2_20261102 --output training/新的目录 --preflight
python tools/run_query_semantic_study.py --data training/query_semantic_data_v2_20261102 --output training/新的目录
python tools/try_query_semantic.py --study training/query_semantic_qlora_v2_20261102 --case test-0000
```

第三条只查看已保存的同题前后输出，不占 GPU。对新问题进行离线推理可加 `--question '问题' --context 上下文.json`；上下文协议见数据文件的 `context`。此模式只输出任务和查询要求，不执行数据库。

## 保留边界

本轮没有充分覆盖风险等级筛选、物理范围内合法查询和历史空洞指标继承；也没有覆盖对象数量、复杂布尔筛选、自定义计算等原系统 SQL 功能。完整对话对照双方均使用 NF4，因此是离线架构对照，不等于线上 FP16 服务的实测准确率。合成任务匹配率不能代替真实用户成功率，实验桥接不能直接替换生产路由。部署与简历表述以最终独立对话结果和报告为准，不使用“解决全部答非所问”或公共基准准确率的说法。

## 2026-11-02 实测结论

**保留为实验，不切换生产默认。** 768条数据完整遍历一次；DEV选择step96，两个检查点复核后的选择不变。训练峰值预留显存11.516GiB。

| 192条合成留出任务 | 基座 | 新适配器 |
| --- | --- | --- |
| 零示例，原始完整任务匹配 | 56 | 160 |
| 零示例，仅归一化等价表示后 | 113 | 160 |
| 相同五示例，原始完整任务匹配 | 80 | 163 |
| 相同五示例，仅归一化等价表示后 | 122 | 163 |

上表证明这组任务协议可以训练适配，但不能证明产品更可靠。完整对话测试得到相反结果：

| 8组24轮完整对话 | 完整原流程 | 新语义桥接 |
| --- | --- | --- |
| 预先规定的严格结果表评分 | 15/24 | 12/24 |
| 允许额外分子/分母列的后验输出覆盖复核 | 16/24 | 12/24 |
| 上项中的SQL查询轮 | 11/18 | 7/18 |
| 全部轮次通过的完整会话 | 2/8 | 1/8 |

输出覆盖复核要求同一返回列投影在三份对比数据库中都正确，不能每份数据库挑不同列。它仍要求查询轮实际执行SQL：原流程有一次从历史结果正确计算出120，但因未执行SQL被扣分，因此上表不是一般意义的回答质量分。

新方案的12个失败轮中，4轮语义任务本已正确，接回原SQL规划后又出现澄清/校验失败；其余包含错误路由、将页面区域误作物理范围以及前轮失败后的上下文连锁错误。因此不能把下降简单归因于QLoRA本身，也不能将单句83.33%包装成SQL正确率。当前桥接把任务再转回自然语言、再次规划，没有充分保住已得到的结构化语义。

结论是：训练、模型产物、检查与实验桥接已实现；**实际功能未达到可替换原流程的程度**。下一次验证应同时补成对范围反例、完整会话状态，并避免重复理解损失。必须使用新的独立测试，不在本轮已见测试上反复调到通过。

611项Python测试通过；原数据库记录、5,984条历史样本和23,936项影像索引检查无变更。Java、Python与视觉演示服务健康，原JAR哈希一致，模型恢复为按需加载。详见 `evaluation/semantic_qlora_20261102/audited_report.json`、`final_health.json` 和 `preservation.json`。原始训练输出在 `training/query_semantic_qlora_v2_20261102/`，原始对话输出在 `evaluation/semantic_qlora_20261102/conversations_v1/`。
