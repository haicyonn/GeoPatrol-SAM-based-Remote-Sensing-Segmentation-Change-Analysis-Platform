# 巡变智判：当前系统说明

2026-11-12：变化检测和单图建筑分割使用同一 Java 后端与原控制台，共用账号、批次、对话问数、协同复核和分析报告。建筑分割使用自己的指标与模型，不冒充双时相结果。分割接入、上传和统计口径见 [分割说明](segmentation/README.md)。

## 唯一正式入口

运行 `start_java_backend.cmd`，访问 **http://127.0.0.1:8786/**。不要直接打开磁盘上的 HTML，也不需要分别启动旧问数页面。

| 入口 | 当前用途 |
| --- | --- |
| 8786 首页 / `index.html` | 正式巡检控制台：影像、问答、复核、报告 |
| 8786 / `manage.html` | 登录、账号、上传批次、执行进度、协作者管理 |
| 8786 / `analysis.html` | 当前批次的分析方案、确认执行、简报与证据导出 |
| 8787 | Java 调用的内部 Python 模型服务，非用户入口 |
| 8766 旧问数页面 | 历史独立演示，不是当前多人系统入口 |
| 8783 视觉演示 | 独立实验，不属于正式批次分析能力 |
| 8777 语音助手 | 另一个项目，不属于巡变后端 |

批次切换、授权、问数均通过同源 Java 接口。首页保留原控制台外观和报告入口，没有用一个独立上传页替代整个系统。详细操作见 [Java 后端说明](backend-java/README.md)。

## 从影像到答案的完整流程

1. **上传并配对。** 创建批次，上传前、后时相影像，按文件名配对，选择已登记的模型。Java 校验文件、记录批次与逐样本任务。
2. **后台变化检测。** Python 执行已有变化检测模型，按需切块、预测并合并掩膜。Java 验证尺寸和统计值，把原图索引、预测结果及模型来源保存到 MySQL。关闭页面不会删除任务记录；失败项可单独重试。
3. **发布本批结果。** 完整批次发布后才进入分析；查看双时相影像和掩膜，查询变化像素、变化比例、连通对象和复核状态。预测结果不等同于人工确认的建筑类别、地面面积或违法结论。
4. **自然语言问数。** Java 从已发布记录构建批次分析数据，Python 在只读 SQLite 数据版本上执行模型生成的 SQL。业务记录由 MySQL 持久化；模型不直接向业务库执行任意 SQL。这是同一业务数据的管理与分析分工。
5. **协同复核与报告。** 人工结论独立保存，使用版本检查处理同时修改；更新后使用新数据版本。区域统计报告与模型规划的多步骤分析简报是两个已有出口，后者需先确认方案，再执行查询并检查数值、结果行引用。

原版 **5,984 条**记录为默认全量样本库。原图和预测保留，管理员可精修，也可按批次授权课题组成员查看或协作。它不冒充本次新推理，也不是准确率或并发性能指标。显式指定批次参数时仍打开该批次；顶部“全量样本库”可返回原数据。

## 人工精修与两个结果视图

“全图总览”按页查看前后时相与掩膜，支持搜索、事件筛选、质量线索筛选；“检测事实”查看原始证据。“协同复核”可切换 T1/T2/系统掩膜底图，逐点绘制多个多边形，Enter闭合、撤销或清空为无变化，并预览修正。

保存绘制草稿只保存当前编辑；选择复核结论后“审批修正并生效”，才使修正影响分析。“恢复原预测”撤销当前生效修正，历史版本继续保留。空多边形集合表示零变化，与恢复预测不同。原图、模型掩膜和原统计没有被覆盖。

顶部“人工修正后／原始预测”控制影像、统计、SQL问数、分析和报告采用同一口径。原始视图只读，切换视图会清理旧会话显示；修正后默认沿用未修改样本的原预测。新修正保存在独立 `sample_annotations` 和不可变 `sample_annotation_history`，兼容原历史ID及新批次UUID。可以导出全部修订历史，Word报告记录结果口径与修正统计。

两人同时修改时后提交者收到409；载入新版本会保留本地几何、未闭合点、备注和结论供核对，只有“放弃本地输入”才清除本地草稿。

## 问数、聊天和澄清的关系

正式链路为 `BatchAssistant → ConversationAssistant → ModelSQL`。原问题、正在浏览的区域、明确选择的查询范围分别传递；查询按认证用户、批次、会话和数据版本隔离。

- 问候、解释概念及明确不执行的请求走聊天。问候中同时包含实际查询，仍处理查询。
- 任务理解生成结构化查询要求，SQL 模型据此生成查询。程序检查字段、范围、排序、计算口径和只读性；失败时有限修复。**SQL 写错不是缺少业务条件，不应让用户补字段。**
- 确实存在多种口径或指代不唯一时，使用已有 `query_clarification.py` 协议追问，页面显示选项。选项绑定原问题、私有字段值和数据版本；既可点击，也可回答选项名称或“第二个”。
- 聊天插入不清空待确认问题；历史加载会恢复选项。已完成、跨会话、跨范围或跨版本的旧选择不能继续执行。
- 已明确的口径可沿用，不会每轮重新问。正在浏览的区域能消解“这个区域”时，也不必额外确认；没有唯一区域时才展示候选。

可按以下流程核对：

> “LEVIR空洞比例是多少？” → 选择“标记样本占比”或“面积比例均值” → 中途说“你好”也保留选择 → 选定后继续原查询。

两个口径分别是“有空洞标记的样本数占全部样本的百分比”和“逐样本内部空洞面积比例的均值”，不能混算。百分比 SQL 须在除法之前转为浮点，不能整数相除后再乘 100。

## 哪些是正式能力，哪些仍是实验

| 内容 | 状态与边界 |
| --- | --- |
| Spring Boot、MySQL、Python 推理、只读问数、协同复核、多边形精修、报告 | 已接入正式控制台 |
| 原排名查询状态 QLoRA | 正式链路已有；只辅助排名状态更新，不负责 SQL 生成 |
| 新多轮语义适配器、直接任务到 SQL 执行器 | 离线实验，**没有切换正式默认**；不能替代现有持久化多人会话 |
| 新实验中的澄清 | 已复用原选项协议，保留原问题与累计选择；不另建 UI 或数据库 |
| 通用结构反馈重试 | 实验无额外收益，默认关闭 |
| 旧 RAG、Agent 和视觉演示入口 | 不能据文件存在就算作当前正式业务链路；不为简历再叠加 |

新适配器的结构匹配成绩不等于 SQL 正确率；调试过的问题是回归集，不再称独立盲测。现存语义误解没有因使用 QLoRA 而全部解决，详见 [语义适配实验记录](docs/semantic-query-repair.md)。

## 本轮检查记录

`evaluation/clarification_flow_20261102/` 保存正式接口与浏览器的澄清流程检查、首次整数除法失败和修复后的记录。自动化测试使用临时数据或专用 QA 会话；结束后禁用 QA 账号、撤销登录。业务原始数据和历史实验不清除。

当前采用单 Java 应用与单 GPU 服务，没有为课题组规模引入微服务、分布式消息中间件或新的 Agent 框架。后续只针对已复现的问题修复和补验证。

全量数据与精修迁移记录见 `evaluation/full_migration_20261102/`：独立数据库40项Java测试、650项Python回归、22项Node测试，以及真实模型SQL的两个结果视图、浏览器绘制/重载/审批/导出检查。原始数据库和源码基线保存在部署机私有备份目录；没有删除旧记录或伪造历史推理。

后续补测发现全量库连续分析存在连接兼容问题：Python的HTTP/1.0响应关闭连接时未显式声明，Java紧随其后的POST可能遇到EOF。已明确发送`Connection: close`，不自动重试可能已执行的请求，并补上真实Python服务的大请求/小请求连续调用测试。实际5,984组全量库的分析页面已走通方案、执行和简报；记录见同目录`io-full-analysis.json`与`io-browser.json`。
