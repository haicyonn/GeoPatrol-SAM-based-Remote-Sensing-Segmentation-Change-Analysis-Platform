# 多轮语义与SQL接入修复

本轮修复前一实验确认的两个问题：范围训练全负例造成的偏差，以及结构化任务重新转回中文、再规划时的信息损失。原生产流程保持默认，旧实验完整保留。

## 直接执行链路

原话与可信上下文 → 语义适配器 → 结构化任务 → 输出与排序契约 → 基座模型写SQL → AST/只读校验 → SQLite结果。

`DirectSemanticQuerySession` 不再调用原任务规划器；`SemanticSQLExecutor` 使用 `selected_samples` 和可选的 `reference_samples` 两个逻辑关系。服务器将区域、实际查询范围、复核/风险过滤与上一轮真实样本ID绑定到逻辑关系，模型无需再次解释这些条件。比较区域全量均值时，参考关系独立绑定，不继承所选ID或复核过滤。

程序检查输出指标、分组、排序、分页、参考子查询的区域关联，禁止额外WHERE、QUALIFY等过滤绕过以及冲突NULL排序。校验通过后，将逻辑关系展开为可信样本来源，继续使用原只读SQLite的权限、函数、长度、步数和时间限制。SQL仍由基座模型生成，评测用确定性编译器不参与生成。

明确聊天或不执行指令保留原系统已有保护，不能被适配器改成查询。原始模型任务匹配另行测量，不用程序保护掩盖模型错误。

## 成对数据

冻结文件 `training/query_semantic_paired_v2_20261102`：1541条训练、144条DEV、197条TEST。为保留完整对照组，条数不强制截断到整数目标。同一句问题在不同页面/物理范围下分别要求正常查询或澄清；有限范围训练含234条正常查询、169条澄清。还覆盖历史空洞口径、复核/风险过滤、待澄清回复和原选样集合。

整组对照和措辞家族按折划分。新训练排除旧DEV、TEST和旧完整对话原句；新DEV/TEST也排除旧实验全部原句。另有30轮新完整对话，原句与新训练、DEV、TEST均不重叠。均为开发者构造的合成领域任务，不是公开基准或真实用户准确率。

## 对照含义

- 完整原流程：保留原路由、规划、SQL校验与排名适配器。
- 旧语义适配器＋直接执行器：衡量接入修复效果，包括保留原明确聊天保护。
- 新语义适配器＋同一执行器：衡量新监督数据和训练效果。

双方均为NF4离线模型。每套系统沿用自己的实际历史；评分器的预期任务和样本ID不传给系统。主要指标要求生成SQL在三份对比数据库上返回所需指标，可带额外分子、分母列，但必须使用同一输出列投影。严格表形状匹配为次要指标。查询轮要求实际执行SQL，聊天内容质量不在该指标中。

新TEST只在DEV选定检查点后推理；旧24轮只作回归，不能算新独立成绩。新模型的原始解析、上下文对照整组正确率与合法/越界范围子集单独报告。全部原始输出、数据/代码哈希和服务恢复记录保留。

## 验证入口与边界

训练和验证使用已有WSL Python环境。`run_query_semantic_study.py` 仅暂停经过PID与命令验证的本项目服务，在成功或失败后分别尝试恢复。数据集和输出目录必须新建，禁止覆盖旧实验。

```bash
python tools/run_query_semantic_study.py --data training/query_semantic_paired_v2_20261102 --output training/query_semantic_repair_v1_20261102 --evidence-directory evaluation/semantic_repair_20261102 --eval-batch 8
python tools/run_query_semantic_study.py --data training/query_semantic_paired_v2_20261102 --output evaluation/semantic_repair_20261102/comparison_v1 --evaluate-study training/query_semantic_repair_v1_20261102 --evaluation-script evaluate_semantic_repair.py --evidence-directory evaluation/semantic_repair_20261102
```

本执行器支持明确的直接SELECT与固定业务指标，不覆盖原系统所有SQL能力，例如每区域内部取前N条、任意联表和自定义表达式。实验会话状态尚不能替代原应用的持久化多人会话。当前不能自动切换为生产默认，也不能把合成解析率写成一般SQL准确率。

## 实测结果与取舍

选定step193（仅由DEV141/144选择），完整遍历1541条训练数据一次。新197条合成留出题上，旧适配器完整任务匹配142/197，新适配器187/197；新范围对照49/49、页面指代对照24/24。该指标不等于SQL正确率。

| 同一30轮对话的修复回归 | 所需结果正确返回 | 完整会话通过 |
| --- | --- | --- |
| 原完整流程 | 16/30 | 2/10 |
| 旧适配器＋修复接入 | 25/30 | 7/10 |
| 新适配器＋相同接入 | 28/30 | 8/10 |

最初独立运行这30轮时，SQL模型仍读到了已绑定的filters:null，并误写IS NULL，得到很差结果（comparison_v1原始记录保留）。修复输入隔离后才得到上表，因此上表必须称修复回归，不能重新称盲测。未改变的原流程和旧适配器原始TEST控制使用哈希核对后复用，记录在manifest中。

随后新增、预先冻结的12轮一次性验收：原流程8/12，新流程9/12。新流程有一条“前2名、列ID及变化像素”被解释成非法标量排名，拖累后两轮。通用结构验证反馈重试实测仍为9/12，没有收益，**schema_repair默认关闭**，仅保留可选实验及原始结果；没有继续堆叠新的默认机制。

项目真实web/app_data.json的6项功能检查全部通过：区域空洞均值第一/第二名、WHU前2样本、原集合求和、原集合与WHU全体均值比较、切换为各区域高风险比例。数据含5984条历史样本。这是实际数据功能检查，不是独立准确率；源数据哈希和完整SQL均保留。

明确保留的错误还包括“最高的区域”遗漏排名，以及“累加”误解成逐样本列表。程序的范围绑定、表达式检查与只读执行不代表模型始终理解正确。新链路仍作为实验组件，原8786网页默认流程未切换。

详细记录：evaluation/semantic_repair_20261102/audited_report.json；comparison_v1保留失败的首次接入结果；comparison_v2保留修复回归、一次性12轮验收和真实数据检查；feedback_regression_v1记录无收益的语义重试。训练产物：training/query_semantic_repair_v1_20261102/step_193。

## 澄清协议补齐（2026-11-02）

原正式链路一直保留结构化选项；此前实验会话仅返回 `action=clarify` 和原因，遗漏了原问题绑定、公开选项和选择续问。现复用 `query_clarification.py` 的 `make_pending/public_pending/resolve_reply`，不新建澄清服务或前端。

已补充区域及空洞口径选项、名称/序号/按钮回复、插入聊天后保留选择、累计选择的约束，以及会话/范围/数据版本变化时拒绝旧选择。用户确认后的指标、明确区域和复核/风险筛选若被语义模型改掉，会阻止执行；不会为了通过校验而悄悄修改用户条件。模型理解期间的版本变化也必须重新提问。

这些修复没有把实验会话接入正式默认，也没有改变既有评测成绩。实验状态仍在内存中；原多人会话仍由正式链路持久化。完整现状以根目录 README.md 为准。
